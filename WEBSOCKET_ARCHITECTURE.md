# WebSocket Architecture — catanFullEndea

Agent-targeted reference. Dense, no prose filler. File:line citations are authoritative; grep them to verify.

---

## 1. Transport

- **Library**: Socket.IO (server `socket.io`, client `io()` global from `/socket.io/socket.io.js`).
- **Not** raw WebSocket. All events are named JSON messages over Socket.IO's default namespace `/`.
- **Server init**: `index.js:6` imports `Server` from `socket.io`; `index.js:18` wraps the Node `http.Server` with `new Server(server)`. Listens on `PORT` (env, default 3000) at `index.js:320-322`.
- **Client init**: `public/js/index.js:12` → `const socket = io()`.
- **Auth context**: HTTP cookies set at `/login` (`game_id`, `player_id`, `spectator_id`, httpOnly, ~5h TTL). The Socket.IO handshake headers carry these cookies; parsed at `index.js:242` via `parseCookie(socket.handshake.headers.cookie)`.

|---|---|

| `public/js/game.js` | Client-side game view/controller. UI events call `socket_manager` emit methods; server broadcasts call `game.update*Soc(...)`. |

## 3. Rooms and sessions

- **One Socket.IO room per game**, keyed by `game_id` (lowercase string like `"apple-river"`, generated by `generateRandomWords` in `index.js:55`).
- All sockets for a game (players + spectators) `socket.join(game_id)` at `index.js:245`. Broadcasts use `io.to(game_id).emit(...)`.
- **No custom namespace** — default `/` only.
- **Session registry**: `GAME_SESSIONS[game_id] = Game instance` (`index.js:38`). In-memory only; server restart wipes everything.
- **Socket-to-game reverse map**: `SOCK_INFO[socket.id] = { game_id, player_id, spectator_id }` (`index.js:252`). Used on disconnect to route cleanup.
- **Spectators**: `player_id === 0`. Added via `game.addSpectator(socket, spectator_id)` (`index.js:248`). Receive broadcasts only, cannot emit game actions.
- **Host**: `game.host_pid` — only player allowed to start game and change config.

---

## 4. State authority model

- **Server-authoritative.** Client is effectively a view.
- Every state mutation (build, roll, trade, dev card, robber, turn advance) happens in `Game` methods on the server. Server then broadcasts diffs or the derived event.
- Clients never mutate state locally before server confirmation; they render from the broadcasts.
- **State sync on HTTP page load** (`index.js:117-165`, route `/game/:id`):
  - Mustache template is rendered with:
    - `game: JSON.stringify(game)` — full `game.toJSON()` (state, board, turn, trades, robber_loc, dev_card deck size, player public data).
    - `player: JSON.stringify(player.toJSON(1))` — the requesting player's full private data (hand, secret dev cards).
    - `opponents: JSON.stringify(game.getOpponents(pid).map(p => p.toJSON()))` — other players' public data (hand counts, visible dev cards, pieces, VPs).
  - Injected into `window.game_obj / window.player_obj / window.opponents_obj`, which the client `Game` class consumes in its constructor (`public/js/game.js:18-55`).
- **State sync on Socket.IO reconnect** (page not reloaded): the socket re-attaches to existing `Game` instance; server re-sends `INITIAL_SETUP` if needed (`game.js:857-860`) and the next `state_change` restores correctness. For anything more than the current state, the client must refresh the page to get a fresh snapshot.

### 5.3 Shared event name pattern `ask/return_*` and `*/ack`

A single wire string is used in **both directions** for request-ack pairs (e.g. `ask/return_initial_setup`, `knight_moves_robber/ack`). Direction is disambiguated by which side registered `.on` vs called `.emit`. When handling, always check *who* sent it; do not assume direction from the string alone.

## 6. Server-side state machine

States live in `public/js/const.js:190-200` (`GAME_STATES`) and are mirrored in `Game.state`:

```
null            → pre-game lobby (waiting_room view)
INITIAL_SETUP   → turns 1-2, each player places 1 settlement + 1 road
PLAYER_ROLL     → active player must roll
PLAYER_ACTIONS  → active player can build/trade/buy/play dev cards/end turn
ROBBER_DROP     → on 7: all players with >hand_limit cards must discard
ROBBER_MOVE     → active player moves robber + steals
END             → game over
```

Every mutation of `Game.state` fires `STATE_CHANGE` broadcast via the `io_manager` (hooked to the setter). Clients branch UI on received `(state, active_pid, turn)`.

**Advance function**: `Game.#next()` (private) determines next state + next active_pid based on current state, recent action, hand sizes after a 7, etc. Always called after an `*IO` handler validates and applies the action.

## 7. End-to-end flows

### 7.1 Lobby → start

1. All entry is `GET` — there is no `POST` route. Host: `GET /game/new` creates the `Game`, sets `game_id`/`player_id` cookies, redirects to `/game/:id` (`index.js:53-115`). Joiner: `GET /login?name=&game_id=` finds or creates the slot, sets the same cookies, redirects (`index.js:167-210`). Spectator: the same route with `&spectate=1`, `player_id` cookie `0`.
2. Client socket connects; `index.js:250` calls `game.setUpPlayerSocket(pid, socket)`.
3. Server broadcasts `JOINED_WAITING_ROOM` with the new player's public data.
4. Client emits `PLAYER_ONLINE`; server sets `player.ready = true`.
5. Host can emit `CHANGE_CONFIG` and `PLAYER_COLOR_CHANGE`; server rebroadcasts.
6. Host emits `START_GAME`. Server calls `game.start()`:
   - `state ← INITIAL_SETUP`, `active_pid ← 1`, `turn ← 1`.
   - Broadcasts `STATE_CHANGE` then `INITIAL_SETUP(active_pid, turn)`.

### 7.2 Initial placement (turns 1-2, snake order)

1. Active client receives `INITIAL_SETUP`; UI highlights legal corners/edges.
2. Client emits `INITIAL_SETUP(settlement_id, road_id)`.
3. Server `game.initialBuildIO`: validate legality → place piece → broadcast `BUILD` (twice: settlement then road) → `UPDATE_PLAYER` (private, deduct nothing on turn 1, grant adjacent resources on turn 2) → `#next()` rotates active_pid (turn 2 reverses direction).
4. When all 2*N placements complete → `state ← PLAYER_ROLL` for pid 1.

### 7.3 Normal turn

```
PLAYER_ROLL
  client → ROLL_DICE
  server: dice.roll() → broadcast DICE_VALUE
    if 7:
      state ← ROBBER_DROP (only for players with hand > limit; else skip)
      each such player → ROBBER_DROP emit with discard map
      after all acked → state ← ROBBER_MOVE
    else:
      for each player gaining: private RES_RECEIVED
      state ← PLAYER_ACTIONS

PLAYER_ACTIONS (repeatable until END_TURN)
  build:       CLICK_LOC → BUILD broadcast + UPDATE_PLAYER private
  buy dev:     BUY_DEV → DEV_CARD_TAKEN private + UPDATE_PLAYER private
  play dev:    KNIGHT_MOVE / ROAD_BUILDING / MONOPOLY / YEAR_OF_PLENTY
               → corresponding ack broadcast + UPDATE_PLAYER private
               → knight transitions through ROBBER_MOVE
  trade req:   TRADE_REQ → TRADE_REQ broadcast + ONGOING_TRADES
  trade resp:  TRADE_RESP → TRADED_INFO broadcast + UPDATE_PLAYER private (both sides)
               + ONGOING_TRADES

END_TURN
  server: #next() → active_pid++ (wraps) → state ← PLAYER_ROLL
```

After any action that can change VP (build settlement/city, dev card VP, longest road, largest army) server runs `#onPlayerVpChange`; if `player.vp >= win_points` → `state ← END` and broadcast `GAME_END`.

### 7.4 Rematch

Handled inline in `index.js:306-356`, not `io_manager`.

1. Each active player emits `REMATCH_VOTE`.
2. Server accumulates in `REMATCH_INFO[gid].votes: Set<pid>`.
3. If non-unanimous → broadcast `REMATCH_PROGRESS([non_voter_names])`.
4. If unanimous → generate new `game_id`, clone config, create new `Game`, broadcast `REMATCH_NEW_GAME({pid: "/login?game_id=...&name=..."})`. Each client redirects self by looking up its own pid in the map.

## 8. Disconnect / reconnect

**On `disconnect`** (`index.js:358-368`):
- Lookup `SOCK_INFO[socket.id]`.
- If `player_id === 0`: `game.removeSpectator(socket, spectator_id)` → broadcast `SPECTATOR_COUNT`.
- Else: `game.removePlayerSocket(pid, socket)` (`models/game.js:863-866`):
  - `player.online = false`, `player.ready = false`.
  - `io_manager.removeEvents(socket)` unbinds all `.on` handlers.
  - Broadcast `PLAYER_QUIT(pid)`.
  - If disconnected player was `active_pid`, `#next()` is invoked to skip them and keep the game unstuck.

**No bot replacement**; game just continues with the player absent. Their assets remain on the board and in their hand.

**On reconnect**:
- Full page load re-fetches `/game/:id`, which re-renders the current server snapshot (see §4).
- New socket → `game.setUpPlayerSocket(pid, socket)` (`models/game.js:850-862`):
  1. `io_manager.removeEvents(oldSocket)` (defensive).
  2. `player.socket = newSocket`.
  3. `io_manager.setUpEvents(newSocket, pid)` re-binds all handlers.
  4. If `state === INITIAL_SETUP` and reconnecting player is `active_pid`, re-emit `INITIAL_SETUP(active_pid, turn)` to un-block them.
- Client emits `PLAYER_ONLINE` → `player.ready = true`.

## 9. Privacy model

The server uses **three emission scopes**:

1. **`io.to(game_id).emit(...)`** — everyone in the room (public events).
2. **`player.socket.emit(...)`** — only that player (e.g. `UPDATE_PLAYER`, `RES_RECEIVED`, `DEV_CARD_TAKEN`, `MONOPOLY`, `YEAR_OF_PLENTY`, `STOLEN_INFO` sent to each of thief and victim).
3. Hand sizes/dev-card counts of opponents are public; the **specific cards** in hand are private. Steals reveal the resource type only to thief and victim; spectators/other players see only that a steal occurred.

When adding new events that carry secret state, use pattern (2): look up target socket by `game.getPlayer(pid).socket`.

## 10. Persistence

- **None.** All state is in `GAME_SESSIONS` (Node process memory).
- Server restart loses all active games. Players hitting `/game/:id` after restart are redirected to `/login?game_id=…` with the key prefilled (`index.js:119-122`).
- Cookies (`game_id`, `player_id`) survive on the client but refer to games that no longer exist post-restart.
- `/api/sessions` and `/api/sessions/clear/:id?salt=…` (`index.js:223-237`) dump and wipe sessions. Both gated by `apiAuthorized` (`API_SALT` env); unset or wrong salt returns `401`.

## 11. Invariants / gotchas for contributors

- **Event strings only from `SOCKET_EVENTS`** (`public/js/const.js:176-223`). A client `socket.emit` with no server `socket.on` is silently dropped — no error, no log.
- **Never mutate `game.state` from outside `Game`.** The setter (`models/game.js:42-45`) is what emits `STATE_CHANGE`; assigning `#state` elsewhere desyncs every client.
- **Never trust client payloads.** Every `*IO` handler re-validates on the server: `#isActive(pid)`, current `state`, legality, cost. Mirror that in any new handler.
- **`expected_actions` is the real gate, not just `state`.** Handlers for queued actions (initial build, robber drop, robber move) must `findIndex` their entry, act, then `splice` it (`game.js:318-323, 380-388, 439-443`). Skipping the splice lets the same action replay; skipping the find lets a non-expected player act.
- **Timers drive transitions.** `setTimer(seconds, fn)` (`game.js:803`) fires `fn` then `#next()`. Any handler that completes a state early must let `#next()` run once — double-advance skips a player. `clearTimer()` before manual advance. With `config.timer` false, timers are no-ops and `#next()` is called directly.
- **Private vs broadcast emits.** Broadcast = `io.to(game_id)`. Private = `io.to(player_socket_id)` (`io_manager.js:101-131`, the `*_Private` methods). Hands, drawn dev cards, steal details and resource receipts are private — putting them on a broadcast leaks the game.
- **`INITIAL_SETUP` is one string used both directions** (`'ask/return_initial_setup'`): server asks, client answers. Same for the `*/ack` events. Register a listener on only one side per process.
- **Host-gated** (`game.js:406-431`): `START_GAME`, `CHANGE_CONFIG`, `ADD_BOT`, `REMOVE_BOT`, `SET_BOT_LEVEL` (all `!this.state`) and `REPLACE_WITH_BOT` (running game, `removed` seat only). All re-check `pid === host_pid` server-side.
- **Bots have no socket.** `models/bots/controller.js` calls the same `*IO(pid, …)` methods a socket handler does, from a `setTimeout` scheduled by `game.onAwaiting`. Never act inside that hook (`#next()` is not re-entrant), and never give a bot a fake socket: `#isAbandoned` counts sockets to decide the game is alive.
- **God mode is per-session and sticky.** `GODMODE_ACTIVATE` (`game.js:772`) needs no authority check by design; `GODMODE_FREE_RES_ACTIVATE` requires god mode already active in that game (`game.js:788`). Free resources then grant on every roll (`game.js:232, 300`) until the game ends.
- **Spectators** (`player_id === 0`) get `addSpectator` only (`index.js:248`); `setUpEvents` returns early without a `pid` (`io_manager.js:20`), so they can receive broadcasts but emit nothing. Keep it that way.
- **Rematch lives in `index.js`** (`index.js:255-304`), not `io_manager` — it spans sessions and creates a new `Game`. Sockets and the session are kept alive after game end so voting works (`game.js:723`).
- **Removed players stay in the array.** `player.removed` is the flag; `players` is indexed by `pid - 1` and never compacted. Any new iteration must filter `!p?.removed`.
- **Dev cards bought this turn can't be played this turn** — `player.turn_bought_dc` (`models/player.js:24, 76, 113`), cleared on turn reset. Server-side only; never move to the client.
- **`SAVE_STATUS` stores client text verbatim** (`game.js:583`) and the client writes it with `innerHTML` (`public/js/ui/alert_ui.js:41`). It is also unguarded against an unknown `pid`. Treat as untrusted before widening its use.
- **Balanced dice** (`config.dice_mode === 'balanced'`) swaps the roll source only (`models/dice.js:145`, see `balanced-dice.md`) and adds `ROLL_DISTRIBUTION` broadcasts. Event wiring is otherwise unchanged.

## 12. Quick reference: adding a new event

1. Add the wire string to `public/js/const.js:176-223` under `SOCKET_EVENTS`.
2. Server handler: add a method `fooIO(args, pid, cb)` on `Game` in `models/game.js`. Validate `pid === active_pid` (or whatever authority rule), validate payload, mutate state, then call broadcaster helper(s).
3. Register the handler: in `models/io_manager.js setUpEvents(socket, pid)`, add `socket.on(CONST.SOCKET_EVENTS.FOO, (...args) => game.fooIO(...args, pid))`.
4. Broadcaster: in `io_manager` broadcaster block, add a method that wraps `io.to(game_id).emit(CONST.SOCKET_EVENTS.FOO_RESULT, ...)` (or `io.to(player_socket_id).emit` for private — see the `*_Private` methods).
5. Client listener: `public/js/socket_manager.js` constructor — `this.socket.on(CONST.SOCKET_EVENTS.FOO_RESULT, (...) => game.updateFooSoc(...))`.
6. Client emitter: method on `socket_manager` + UI wiring in `public/js/game.js`.
7. Unit test: see `tests/` for existing patterns (e.g. `dice_test.js`).
